# 실기기까지 가는 길 — 단계별

`native/`의 앱을 아이폰에 올려서 **긋는 손맛을 확인하기까지**의 순서다.

표시 둘만 보면 된다:

- **【제가 합니다】** — 코드·git·검사·번들. 알려 주시면 제가 하고 결과만 보고합니다.
- **【눌러 주세요】** — 계정으로만 되는 일. 메뉴 → 탭 → 버튼 순서로 적었습니다.

**이 문서에서 사용자가 저에게 넘겨줘야 하는 값은 셋뿐입니다** (2·4단계):
Expo 프로젝트 ID, 애플 팀 ID, 그리고 번들 ID를 바꾸고 싶을 때 그 이름.

---

## 0단계 — 이미 되어 있는 것

| | 상태 |
|---|---|
| 코드 | `native/`에 전부 (긋기·지우개·칸 나누기·펜·소리·진동·저장·동기화·위젯) |
| 검사 | 110개 통과 (기기 없이 도는 것들) |
| 번들 | iOS 번들 통과 — 문법·의존이 다 맞습니다 |
| 실기기 | **아직 아무것도 확인되지 않았습니다.** 여기가 이 문서의 목적입니다 |

## 1단계 — 계정 둘 【눌러 주세요】

### 1-1. 애플 개발자 프로그램 ($99/년)

없으면 여기서 시작합니다. 위젯도 실기기 설치도 이것 없이는 안 됩니다.

> developer.apple.com → 오른쪽 위 **Account** → 로그인 →
> **Join the Apple Developer Program** → **Enroll** → 개인/법인 선택 → 결제

승인까지 보통 하루 안쪽입니다. **승인 전에는 아래 3·5·6단계가 안 보입니다.**

### 1-2. Expo 계정

빌드를 클라우드에서 돌리는 자리입니다. 무료로 시작할 수 있습니다.

> expo.dev → 오른쪽 위 **Sign Up** → 이메일·비밀번호 → 가입

## 2단계 — Expo 프로젝트 만들기 【눌러 주세요】 → 값 하나 주세요

> expo.dev → 로그인 → 왼쪽 **Projects** → **Create a Project** →
> Name에 `Clear Week`, Slug에 `clear-week` → **Create**

만들어지면 프로젝트 화면 위쪽에 **Project ID**(`xxxxxxxx-xxxx-…` 모양)가 보입니다.
계정 이름(Owner, 보통 가입할 때 정한 username)과 함께 알려 주세요.

**【제가 합니다】** 두 값을 `app.json`에 넣고(`owner`, `extra.eas.projectId`)
커밋·푸시합니다. 이게 있어야 EAS가 "어느 프로젝트의 빌드인지" 압니다.

## 3단계 — GitHub를 Expo에 연결 【눌러 주세요】

CLI 없이 **웹에서 빌드 버튼을 누르기 위한** 연결입니다.

> **3-1. 계정 연결**
> expo.dev → 오른쪽 위 계정 아이콘 → **Settings** → **Connections** →
> GitHub 줄의 **Connect** → **Get started** →
> (깃허브 창) **Install and Authorize** → (다시 Expo 창) **Link installation**

> **3-2. 저장소 연결**
> expo.dev → **Projects** → `Clear Week` → **Project settings** → **GitHub** →
> **Connect a GitHub repository** → 목록에서 `stupidpoohh-tech/clear-week` 선택

> **3-3. ★ 여기서 한 곳만 바꿉니다**
> 같은 화면의 **Base directory**(기본값 `/`)를 **`/native`** 로 고칩니다.
> 앱이 저장소 뿌리가 아니라 `native/` 안에 있기 때문입니다.
> 이걸 안 바꾸면 빌드가 "앱을 못 찾겠다"며 실패합니다.

## 4단계 — 애플 팀 ID 【눌러 주세요】 → 값 하나 주세요

> developer.apple.com → **Account** → 왼쪽 **Membership details** →
> **Team ID** (열 글자쯤 되는 영문+숫자) 복사

알려 주시면 **【제가 합니다】** `app.json`의 `appleTeamId`를 그 값으로 바꾸고
커밋·푸시합니다. 지금은 `REPLACE_WITH_TEAM_ID`가 들어 있어서, **이 값을 넣기
전에는 위젯 타겟이 빌드되지 않습니다.**

## 5단계 — App Group 만들고 붙이기 【눌러 주세요】

**앱과 위젯이 만나는 자리는 이것 하나뿐입니다.** 앱이 여기에 주간표를 적어 두면
위젯이 읽습니다. 없으면 위젯이 늘 비어 있습니다.

> **5-1. 그룹 만들기**
> developer.apple.com → **Account** → **Certificates, Identifiers & Profiles** →
> 왼쪽 **Identifiers** → 목록 오른쪽 위 드롭다운을 **App Groups** 로 바꿈 →
> **＋** → Description `Clear Week`, Identifier `group.dev.clearweek` →
> **Continue** → **Register**

> **5-2. 앱에 붙이기** (앱 ID는 첫 빌드 때 EAS가 자동으로 만듭니다.
> 그러니 **8단계 첫 빌드를 한 번 돌린 뒤에** 이 항목을 합니다)
> 같은 **Identifiers** → 드롭다운을 **App IDs** 로 → `dev.clearweek.app` 클릭 →
> **Capabilities** 목록에서 **App Groups** 체크 → 오른쪽 **Edit** →
> `group.dev.clearweek` 체크 → **Continue** → **Save**

> **5-3. 위젯에도 같은 것을**
> 같은 목록에서 `dev.clearweek.app.widget` → **App Groups** 체크 → **Edit** →
> `group.dev.clearweek` 체크 → **Save**

붙인 뒤에는 **빌드를 한 번 더** 돌려야 반영됩니다 (8단계).

---

## 6단계 — 애플 로그인 없이 빌드되게 하는 열쇠 【눌러 주세요】

빌드할 때마다 애플 2단계 인증을 하지 않으려면 **App Store Connect API 키**를
한 번 만들어 Expo에 올려 둡니다. (이 키가 없으면 빌드 도중 애플 로그인을
요구하는데, 그건 웹 화면에서 처리하기 번거롭습니다.)

> **6-1. 키 만들기**
> appstoreconnect.apple.com → **Users and Access** → **Integrations** 탭 →
> 왼쪽 **App Store Connect API** → **Team Keys** → **＋** →
> Name `EAS`, Access **Admin** → **Generate** →
> **Download API Key**(.p8 파일 — **한 번만 받을 수 있습니다**) →
> 같은 화면의 **Issuer ID**와 **Key ID**도 함께 적어 둡니다

> **6-2. Expo에 올리기**
> expo.dev → **Projects** → `Clear Week` → 왼쪽 **Credentials** →
> **iOS** → **App Store Connect API Key** → **Add** →
> Issuer ID·Key ID를 넣고 .p8 파일 업로드 → 저장

## 7단계 — 아이폰 등록 【눌러 주세요】

내부 배포(internal distribution)는 **등록된 기기에만** 설치됩니다.

> expo.dev → 오른쪽 위 계정 아이콘 → **Settings** → **Apple devices** →
> **Register a device** → 나오는 **QR 코드를 아이폰 카메라로** 찍거나 링크를 아이폰에서 엶 →
> 사파리가 프로파일을 내려받음 →
> 아이폰 **설정** 앱 맨 위 **다운로드된 프로파일** → **설치** → 암호 입력 → **설치**

아이패드에서도 쓸 예정이면 아이패드로 한 번 더 합니다.
**등록한 기기가 프로비저닝에 들어가는 시점은 다음 빌드 때입니다.**

## 8단계 — 빌드 걸기 【눌러 주세요】 (또는 제가 밀면 자동)

> expo.dev → **Projects** → `Clear Week` → 왼쪽 **Builds** →
> 오른쪽 위 **Build from GitHub** →
> Git ref: `claude/clear-week-react-native-c27js7` /
> Platform: **iOS** / Build profile: **device** → **Build**

`device` 프로파일이 내부 배포입니다 (`native/eas.json`에 이미 적어 두었습니다).

첫 빌드는 15~25분쯤 걸립니다. 실패하면 그 화면의 로그 마지막 30줄을 알려 주세요 —
**【제가 합니다】** 원인을 잡아 고치고 다시 밀겠습니다.

## 9단계 — 아이폰에 설치 【눌러 주세요】

> 빌드가 끝난 화면에 뜨는 **QR 코드를 아이폰 카메라로** 찍음 →
> **Install** → 홈 화면에 `Clear Week` 아이콘이 생김

처음 열 때 "신뢰되지 않은 개발자"가 뜨면:

> 아이폰 **설정** → **일반** → **VPN 및 기기 관리** →
> 개발자 앱 아래 당신의 팀 이름 → **신뢰**

## 10단계 — 무엇을 봐 주셔야 하나

**순서가 중요합니다. 1번이 이 제품의 갈림길입니다** — 여기서 아니라면 그 뒤는
의미가 없습니다. 하나씩 보시고 "됐다 / 이상하다 + 어떻게 이상한지"만 알려 주시면
**【제가 합니다】** 고쳐서 다시 밀겠습니다.

| 순서 | 무엇을 | 어떻게 보나 | 무엇이 이상한 것인가 |
|---|---|---|---|
| 1 | **긋는 손맛** | 항목 글자 위를 손가락으로 좌→우로 그어 본다 | 선이 손가락을 따라 **자라나지 않고** 뗄 때 나타남 / 획이 뚝뚝 끊김 / 종이 느낌이 안 남. **웹(clear-week.pages.dev)과 번갈아 해 보시면 기준이 생깁니다** |
| 2 | 확정과 되감기 | 글자의 절반쯤만 긋고 떼 본다 → 되감겨 사라져야 함. 60% 넘게 그으면 남아야 함 | 남아야 할 것이 사라지거나, 사라져야 할 것이 남음 |
| 3 | 지우개 | 그어진 줄 위를 좌우로 문댄다. **여러 줄에 걸쳐 넓게도** 문대 본다 | 한 줄만 지워짐 / 손 떼면 얼룩이 남음 (다 지워지거나 온전히 돌아와야 합니다) |
| 4 | 삭제 | 항목을 0.5초 꾹 누른다. 누른 채로 아래로 끌어도 본다 | 안 지워짐 / 안 눌렀는데 지워짐 |
| 5 | **애플펜슬** | 빈 칸에 펜을 대고 **그냥 쓴다**(탭 없이). 그 다음 **이미 적힌 글자 위를 펜으로 긋는다** | 글자가 안 들어감 / **긋기가 새 글자로 들어감** ← 웹에서 가장 크게 밟은 함정입니다 |
| 6 | 소리 | 그을 때 사각사각, 글자 칠 때 톡. 무음 스위치를 켠 채로도 | 톡이 사각사각보다 크게 들림 / 무음에서 안 남 / 껐는데 남의 앱 소리가 안 돌아옴 |
| 7 | 진동 | 획이 확정될 때, 잉크가 다 벗겨질 때 | 없음 / 너무 셈 |
| 8 | 자판 | 항목을 탭해 편집할 때 | **표가 위로 밀려 올라감** (한 화면 고정이 깨지면 큰 문제입니다) |
| 9 | 항목 높이 | 26으로 두었습니다 | 긋기에 좁게 느껴지면 알려 주세요. 초안은 44였습니다 |

## 11단계 — 위젯 【눌러 주세요】

5단계(App Group)를 마치고 빌드를 한 번 더 돌린 뒤입니다.

> 홈 화면 빈 곳을 꾹 누름 → 왼쪽 위 **＋** → 검색창에 `Clear Week` →
> 중간/큰 크기 고르고 **위젯 추가**

앱에서 항목을 하나 적고 홈 화면으로 나가면 위젯에 같은 것이 보여야 합니다.
비어 있으면 App Group이 안 붙은 것입니다 (5단계로).

## 12단계 — 로그인·캘린더를 쓸 때만 【눌러 주세요】

**로그아웃 상태의 앱은 서버를 전혀 건드리지 않습니다.** 손맛만 보실 거면
이 단계는 건너뛰어도 됩니다.

> **12-1. 이메일 로그인이 켜져 있는지**
> console.firebase.google.com → 프로젝트 `dada-calendar-524ec` →
> 왼쪽 **Authentication** → **Sign-in method** 탭 →
> **이메일/비밀번호**가 **사용 설정됨**인지 확인
> (캘린더가 이미 쓰고 있으므로 대개 켜져 있습니다)

> **12-2. ★ API 키 제한 — 여기서 막힐 수 있습니다**
> 웹에서는 키를 "HTTP 리퍼러"로 묶어 두는 일이 흔한데, 그렇게 묶여 있으면
> **앱에서는 로그인이 통째로 실패합니다.**
> console.cloud.google.com → 위쪽 프로젝트 선택기에서 `dada-calendar-524ec` →
> 왼쪽 **API 및 서비스** → **사용자 인증 정보** →
> Browser key(웹 API 키) 클릭 → **애플리케이션 제한사항**
> · **없음**이면 그대로 두면 됩니다
> · **HTTP 리퍼러**로 되어 있으면 → **iOS 앱** 으로 바꾸고
>   번들 ID `dev.clearweek.app` 추가 → **저장**
>   (웹도 같은 키를 쓰고 있으면 키를 하나 더 만드는 편이 낫습니다.
>    그때는 말씀해 주세요 — **【제가 합니다】** 앱 쪽 키를 새 값으로 바꾸겠습니다)

Firestore 규칙은 손대지 않습니다 — 이 앱은 캘린더를 **읽기만** 합니다.
"승인된 도메인"도 웹 SDK용이라 네이티브와 무관합니다.

## 13단계 — 판정 뒤

1번(손맛)의 답에 따라 갈립니다.

- **웹보다 낫다** → 다음은 항목 높이(26 vs 44) 같은 값 조정, 그리고
  로그인을 iCloud(CloudKit)로 갈아탈지의 결정입니다 (spec §11).
  갈아탈 자리를 위해 동기화는 `src/sync/` 안에만 두었습니다.
- **웹만 못하다** → 무엇이 못한지가 중요합니다. 획이 늦는지(그리는 쪽),
  손짓이 늦는지(받는 쪽), 모양이 다른지(값). 셋은 고치는 자리가 다릅니다.
  알려 주시면 **【제가 합니다】** 그 자리부터 봅니다.

## 값 셋 — 정리

제가 못 만드는 값입니다. 이것만 주시면 나머지는 제가 넣습니다.

| 값 | 어디서 | 제가 어디에 넣나 |
|---|---|---|
| Expo Project ID + 계정 이름 | expo.dev → Projects → Clear Week (2단계) | `app.json`의 `owner`·`extra.eas.projectId` |
| 애플 Team ID | developer.apple.com → Account → Membership details (4단계) | `app.json`의 `appleTeamId` |
| (선택) 번들 ID를 바꾸고 싶다면 | — | `app.json`의 `bundleIdentifier`, App Group 이름, 위젯 Swift 한 줄 |
